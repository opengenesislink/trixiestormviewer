# TrixieStorm Viewer — source rebranding

**Status (2026-11-08): implemented at source level in `feature/firestorm-source-import`, PR #1; not merged to main or proven by an executable build.**

## Renamed application identities

| Surface | Source identity |
|---|---|
| Viewer channel/title | `TrixieStorm Viewer` |
| CMake root product | `TrixieStorm` |
| Internal binary | `trixiestorm-bin` |
| Windows installed executable | `TrixieStormViewer.exe` |
| Installer and metadata | TrixieStorm Viewer, independent OpenGenesisLINK registration |
| Linux launcher/desktop | `trixiestormviewer`, `trixiestormviewer.desktop` |
| User settings/cache | `TrixieStormViewer_x64` / `TrixieStormViewer` |
| Crash logger | TrixieStorm naming |
| UI | Main English/German settings, menus, login and help text |
| Windows/Linux icons | Project-supplied art processed into ICO, PNG, BMP and login texture |

The pinned Firestorm base is `Firestorm_7.2.4` commit `10bd3c9f930c76e1427ddd4ecece6cdf36b4406d`. The original import uses `scripts/rebrand_firestorm.py`, followed by supplementary source fixes in PR #1. Art assets are generated by `scripts/build_brand_assets.py`; source consistency is checked with `scripts/audit_branding.py`.

## What deliberately retains its original upstream names

Firestorm/Linden Lab contributor and license notices, third-party attribution, native `fs_*` module identifiers, source `FSL*` classes, older internal skins and inventory folder IDs needed for compatibility. Changing these universally could break source or data compatibility. Some non-English locales and macOS legacy packaging remain to be reviewed.

## Validate and release

```bash
python3 scripts/audit_branding.py
git diff --check
# Then perform real Linux x64 and Windows x64 ReleaseOS builds and smoke tests.
```

A passing source audit **does not** prove C++ compilation, installer integration, logo quality on display or correct runtime paths. The latest test workflow is `.github/workflows/branding-audit.yml`. Full-size logo should be substituted before public release.

NexVerse-only Gen1/Gen2 login, Hypergrid blocking and per-generation session isolation remain separate unimplemented tasks; see `docs/GRID_POLICY.md`.
